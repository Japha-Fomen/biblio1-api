SécuritéSecurity

Authentification HTTP Basic sans session, mots de passe hachés en BCrypt, autorisation par rôles appliquée route par route sur trois niveaux. L’ordre des règles compte : les plus spécifiques passent avant les plus larges, faute de quoi une règle générale exposerait une ressource protégée. L’inscription est publique et n’accorde que le rôle lecteur. L’attribution des rôles est réservée à l’administrateur, ce qui empêche un bibliothécaire de se promouvoir lui-même.

Stateless HTTP Basic authentication, BCrypt password hashing, and role based authorization applied route by route across three levels. Rule order matters: the most specific rules come before the broader ones, otherwise a general rule would expose a protected resource. Registration is public and grants the reader role only. Role assignment is restricted to administrators, which prevents a librarian from promoting themselves.

ConceptionEngineering

  • Architecture en couches, DTO distinct par opération, validation à l’entrée.
  • Gestionnaire d’exceptions centralisé : chaque erreur devient un code de statut exact et un corps JSON qui nomme les champs fautifs, sans fuite d’information interne.
  • Schéma géré par migrations Flyway versionnées, pour MySQL en développement et PostgreSQL en déploiement.
  • Intégration continue qui compile et teste à chaque poussée, image Docker en deux étapes d’environ 200 Mo.
  • Collection Postman de 47 requêtes en huit dossiers, couvrant le parcours nominal, les entrées rejetées, les conflits métier et le scénario complet d’emprunt et de retour.
  • Layered architecture, one DTO per operation, validation at the boundary.
  • Centralized exception handler: every failure becomes an accurate status code and a JSON body naming the invalid fields, with no internal detail leaking out.
  • Schema managed by versioned Flyway migrations, for MySQL in development and PostgreSQL in deployment.
  • Continuous integration building and testing on every push, two stage Docker image of about 200 MB.
  • Postman collection of 47 requests in eight folders, covering the nominal flow, rejected input, business conflicts and the full borrow and return scenario.

Limites connuesKnown limitations

  • Les règles qui dépendent du lien entre l’appelant et la ressource visée sont encore en cours d’implémentation dans la couche de service. Seule l’autorisation par route est en place.
  • La mise à jour automatique des emprunts en retard n’est pas encore branchée.
  • Les tests actuels sont une collection Postman. La couverture JUnit est le prochain chantier.
  • Les livres et auteurs visibles sont un jeu de données de démonstration.
  • Rules that depend on the relationship between the caller and the target resource are still being implemented in the service layer. Only route level authorization is in place today.
  • Automatic flagging of overdue loans is not wired up yet.
  • Current tests are a Postman collection. JUnit coverage is the next piece of work.
  • The books and authors on display are a demonstration data set.
Service déployé sur Google Cloud Run avec une base PostgreSQL gérée. L’instance et la base se mettent en veille après une période d’inactivité, donc le premier appel peut prendre jusqu’à une minute. Projet d’apprentissage construit seul : le modèle en couches est la première étape, la suite prévoit un découpage par domaines puis une architecture en services. Deployed on Google Cloud Run against a managed PostgreSQL database. Both the instance and the database sleep after a period of inactivity, so the first call can take up to a minute. A learning project built alone: the layered model is the first step, with a move to domain oriented packaging and then a service architecture planned next.
